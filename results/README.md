# Results

Generated by `adaptive_charge_state_master.py` at commit `b5c336f`, full sample
size (700 calibration + 1800 test shots per initial state, 300 bootstrap
resamples), physics layer `builtin-reference`.

**Bootstrap correction.** These runs supersede an earlier set whose confidence
intervals were wrong. The matched-fidelity point estimate interpolates over the
full configuration grid, but each resample was pruned to the
calibration-frontier subset first, which makes the interval an estimate of a
different quantity. The point estimate fell outside its own 95% interval in
26% of rows for adaptive MMPP and 44% for the fixed-count methods, always
below. Resampling over the full grid fixes it: 0.1% of 2081 rows now fall
outside, the expected percentile-boundary residue. The corrected intervals are
about 35% **wider** (median width 0.073 against 0.049 on power/ideal), because
pruning had removed the configuration-selection noise from the resampling and
so understated the uncertainty. Every point estimate, fidelity ceiling and
decomposition below is numerically unchanged; only the intervals moved.

All 5 experiments were run under 3 detector settings, 15 combinations total:

```
results/<experiment>/<detector>/
    <experiment>_sweep.png      fidelity vs run time, and all three speedup curves
    <experiment>_vs_x.png       speedup and fidelity ceiling vs the swept variable
    speedup_table.csv           every target fidelity, every method, bootstrap CIs
    fidelity_ceilings.csv       best achievable fidelity per method
    summary.txt                 the text summary, as printed by `summary`
```

Detector directories: `ideal`, `det_nonpar_dt50ns_ap0.01_tau100ns` (the
`realistic` preset), `det_nonpar_dt2000ns_ap0.05_tau5000ns` (`stress`).

Not committed, both regenerable: the per-shot pickles (~1.3 GB — they carry the
correctness and stop-time matrices so the bootstrap can be redone without
re-simulating; `run`) and the per-operating-point figures (`plot`).

## The four methods

| stopping rule | decision statistic | method |
|---|---|---|
| fixed time | photon count | 1 fixed-time threshold (baseline) |
| fixed count (n-th photon) | count — one bit | 2 adaptive count SPRT |
| fixed count (n-th photon) | MMPP LLR | 3 fixed-count MMPP |
| LLR boundary | MMPP LLR | 4 adaptive MMPP SPRT |

Methods 2 and 3 stop at identical instants — `validate` asserts exact equality
of their per-shot stop times, so their mean run times are identical by
construction. That makes 2 → 3 a clean read on the **decision statistic** with
stopping held fixed, and 3 → 4 a clean read on the **stopping rule** with the
statistic held fixed.

## How to read these numbers

**The speedup depends strongly on *where* on the fidelity axis you ask.** The
fixed-time threshold curve is non-monotone: fidelity rises, peaks, then falls as
the charge state scrambles. So `t_threshold` diverges as the target approaches
the threshold's own ceiling, and the speedup diverges with it. Pooling all
targets, the median reduction is only 1.08–1.14×; the per-point *maxima* of
1.4–2.4× all sit within a hundredth or two of the ceiling, and are maxima over
~45 correlated targets, so they are biased upward.

Medians by headroom below the threshold's own ceiling (693 rows where the
adaptive MMPP speedup is defined):

| [0.01, 0.02) | 23 | 1.33× | 1.09× | 1.13× |

## Headline: the speed comes from the stopping rule, the accuracy from the statistic

This is what the fixed-count MMPP control was added to resolve, and it **corrects
an earlier reading of these runs.** Before the control existed, the only
available comparison was adaptive MMPP against adaptive count, a ratio of about
1.09 that bundles both changes at once; it was natural — and wrong — to read
that as the event-time statistic paying off.

Factoring at matched target, as medians of per-row ratios:

| step | what changes | factor |
|---|---|---|
| threshold → adaptive count | stopping rule: fixed time → fixed count | 1.046× |
| adaptive count → fixed-count MMPP | decision statistic: count → MMPP LLR | **1.000×** |
| fixed-count MMPP → adaptive MMPP | stopping rule: fixed count → LLR boundary | **1.094×** |

Swapping in the MMPP likelihood while holding the stopping rule fixed buys
essentially **no speed at all** — median 1.0000, above 1.01 in only 3% of the
685 rows both methods reach. All of the run-time reduction comes from *when* the
rule decides to stop, not from *what* statistic it stops on. Separately:

| method | median speedup | CI above 1 | CI below 1 | max |
|---|---|---|---|---|
| adaptive count (stopping only) | 1.046× | 46% | 27% | 1.68× |
| fixed-count MMPP (statistic only) | 1.045× | 45% | 26% | 1.60× |
| adaptive MMPP (both) | 1.121× | **82%** | **0.1%** | 2.38× |

Read the middle column as "significantly faster than the baseline" and the
right one as "significantly slower". Both fixed-count methods are significantly
slower in about a quarter of rows — that is the 0.78× far-from-ceiling band
above, now with intervals tight enough to exclude 1 on the wrong side. Only the
LLR-boundary rule is essentially never significantly slower, and it is the only
one significantly faster in a large majority of rows.

The reason is structural, and obvious in hindsight: methods 2 and 3 have
*identical* run-time distributions by construction, so a better statistic can
only lift the fidelity-vs-time curve **up**, never shift it **left**. Speed at
matched fidelity is a horizontal displacement, and only a data-dependent
stopping rule produces one.

**Where the statistic does pay is accuracy and reachability.** At identical run
times the MMPP LLR beats the one-bit count statistic almost everywhere — in one
full-size operating point it was strictly better in 220 of 224 configurations
and never worse — and it raises the achievable ceiling:

| step | mean ceiling gain |
|---|---|
| adaptive count → fixed-count MMPP (statistic) | **+0.0089** |
| fixed-count MMPP → adaptive MMPP (LLR stopping) | +0.0014 |

So the two axes divide cleanly, and in opposite directions from the naive
reading: the **statistic** is worth ~6× more than the stopping rule for
*fidelity*, and the **stopping rule** is worth essentially all of the *speed*.
Fixed-count MMPP also reaches 9 (point, target) combinations the count rule
cannot reach at any configuration, while never failing to reach one the count
rule can — and its ceiling beats the fixed-time threshold's at 20 of 23
operating points, which the count rule manages at only 1.

Practical reading: if you are limited by fidelity, the event-time likelihood is
the thing to implement, and you can keep a trivially simple "stop at the n-th
photon" trigger. If you are limited by throughput, you need the sequential
boundary test, and its real-time LLR evaluation, to get anything at all.

## One parameter controls the speedup: photons per bright dwell

With headroom matched, the sparsity parameter λ₋/Γ₋₀ explains most of the
between-point variation in the adaptive-MMPP speedup:

```
log(speedup) = 0.086 + 0.063 log(photons per bright dwell)     R² = 0.77, n = 23
```

A factor of 10 more photons per bright dwell buys about **1.16×** more speedup.
Adding contrast as a second regressor changes nothing (coefficient +0.013,
R² unchanged at 0.77).

This is the mechanism working as predicted. The event-time filter can only beat
a photon count when the arrival *pattern* within a dwell carries information the
total does not, which requires several photons per dwell. Below ~1 photon per
bright dwell the count is very nearly a sufficient statistic: at η = 0.02
(0.21 photons per dwell) the speedup is 1.02×, and the fixed-count MMPP ceiling
actually falls slightly *below* the count rule's (0.570 vs 0.574) — with almost
no photons to time, the extra freedom in the cutoff is fitting calibration
noise.

**Contrast and switching ratio move the ceiling, not the speedup.** Both sweeps
look like they have a speedup trend if you take the per-point maximum —
contrast appearing to peak at C = 0.85, the ratio appearing to rise to 1.6× —
but at matched headroom the contrast speedups (1.18–1.41×) sit inside CI widths
of 0.14–0.54 and the ratio speedups (1.25–1.33×) inside widths of 0.11–0.17.
Neither trend is resolved. The corrected wider intervals make the ratio trend
less resolved than it looked before: its entire 0.08 spread is now narrower
than a single point's interval. What *is* clean and monotone in both sweeps is the
achievable fidelity:

- contrast 0.50 → 0.99 raises the MMPP ceiling 0.785 → 0.932
- ratio 0.5 → 100 raises it 0.885 → 0.931

Physically sensible: contrast and the bright/dark asymmetry determine how
distinguishable the two initial states are at all, whereas the speedup is about
how efficiently a given amount of distinguishability is extracted per unit time.

## Nothing here beats the D'Anjou bound

Only 3 of 693 ideal-detector rows exceed the 2× reduction that D'Anjou gives as
the bound for decay readout, and in none of them does the CI lower bound clear 2:

| point | F* | speedup | 95% CI | t_thr | t_mmpp |
|---|---|---|---|---|---|
| 4 µW | 0.92 | 2.38× | [1.34, 2.68] | 66.3 µs | 27.8 µs |
| 2 µW | 0.95 | 2.08× | [1.66, 2.22] | 98.4 µs | 47.2 µs |
| 0.875 µW | 0.96 | 2.00× | [1.27, 2.10] | 174.5 µs | 87.2 µs |

All three are near-ceiling maxima, where the estimator is noisiest. Read as
consistent with the bound, not as clearing it.

## What an experiment would actually gain

Adaptive readout shortens the measurement window only. Per-shot initialization,
spin manipulation and reset dilute it:

| point | F* | t_thr | t_mmpp | 0 µs | 5 µs | 20 µs | 100 µs overhead |
|---|---|---|---|---|---|---|---|
| 0.875 µW | 0.96 | 174.5 µs | 87.2 µs | 2.00× | 1.95× | 1.81× | 1.47× |
| 2 µW | 0.95 | 98.4 µs | 47.2 µs | 2.08× | 1.98× | 1.76× | 1.35× |
| 4 µW | 0.92 | 66.3 µs | 27.8 µs | 2.38× | 2.17× | 1.80× | 1.30× |
| 8 µW | 0.87 | 29.2 µs | 18.2 µs | 1.61× | 1.48× | 1.29× | 1.09× |
| 15 µW | 0.80 | 16.5 µs | 12.0 µs | 1.38× | 1.27× | 1.14× | 1.04× |

The low-power points survive overhead best, because their absolute run times are
longest. The practical sweet spot is **low power with high collection
efficiency**, run at a target close to the threshold's ceiling: simultaneously
where sparsity is highest, where the threshold's turnover is sharpest, and where
the saved microseconds are large enough to matter against overhead. High power
is the worst case on every axis at once.

## Effect of the detector model

Dead time and afterpulsing do **not** overturn any of this. Comparing peak
speedups across detector settings, the differences are comparable to the
bootstrap width rather than systematic:

| experiment | ideal | realistic | stress |
|---|---|---|---|
| power, 0.875 µW | 2.00× | 2.07× | 2.08× |
| power, 15 µW | 1.38× | 1.24× | 1.31× |
| contrast, C = 0.85 | 1.79× | 1.82× | 2.01× |
| efficiency, η = 1.0 | 1.45× | 1.38× | 1.43× |
| ratio, Γ₋₀/Γ₀₋ = 100 | 1.62× | 1.44× | 1.52× |

The `realistic` preset (50 ns dead time, 1% afterpulsing) perturbs the recorded
rate by well under a percent, so this is expected there. The `stress` preset is
a real perturbation — 2 µs dead time against an 11.6 µs mean bright-photon
spacing, costing ~12% of clicks — and the speedup still holds, because the
filter is rebuilt from the dead-time/afterpulse-corrected rates and both methods
lose the same photons.

The fidelity *ceilings* are likewise not measurably degraded. Across the 23
operating points, the adaptive-MMPP ceiling shifts by a mean of −0.0013 under
`stress` (range −0.014 to +0.013, 14 of 23 negative) and +0.0004 under
`realistic`. With 1800 test shots per initial state that scatter is what
Monte Carlo noise alone produces, so this matrix does not resolve a ceiling
penalty — it bounds one at roughly ±0.01, not that there is none. Resolving a
smaller effect needs more shots or a common-random-numbers comparison; each
detector setting consumes the RNG differently, so the runs are effectively
independent rather than paired.

Caveat carried in the code: with the detector on, the stream is no longer a
Markov-modulated *Poisson* process, so the MMPP likelihood is approximate and
the reported LLR is a score rather than an exact log-likelihood ratio. Run with
`--no-filter-correction` to see what pure model mismatch costs instead.

## Caveats

- **Physics layer.** These runs use `builtin-reference`, not
  `nv_charge_readout_master_v1_4`. The rate model is pinned to the same 5.437 µW
  operating point (Γ_tot = 9.42 kHz, p_bright = 0.118) but the power dependence
  and the emission rates are a documented stand-in. Re-run with the real module
  before quoting any number. Every CSV and summary records the layer used.
- **Selection bias in the peaks.** Per-point maxima are maxima over ~45
  correlated targets and are biased upward. The matched-headroom medians are the
  defensible statistic.
- **The ratio sweep is not a clean one-parameter sweep.** Holding Γ_tot fixed
  means changing Γ₋₀/Γ₀₋ also changes Γ₋₀, so photons per bright dwell drifts
  27.5 → 9.3 across it. Given the sparsity law above, that alone predicts a
  ~1.07× *decrease*, against a roughly flat observation — so the ratio has a
  mild compensating positive effect that this design cannot separate.
- **The fixed-count MMPP cutoff is fitted, the count rule's is not.** Method 3
  calibrates a real-valued LLR cutoff on calibration data while method 2's
  decision has no free parameter beyond `n_up`, which the grid already sweeps.
  At η = 0.02 that extra freedom costs it slightly (ceiling 0.570 vs 0.574), so
  the statistic's ceiling advantage is not uniform — it needs photons to work
  with.
- **Test-set frontier.** Every method is optimized on the test set, which is
  symmetric between them and matches published figures where t_R and the count
  threshold are both tuned, but it is not an out-of-sample number.

## Reproducing

```bash
python adaptive_charge_state_master.py run  <experiment> --out results [detector flags]
python adaptive_charge_state_master.py plot <experiment> --out results [detector flags]
python adaptive_charge_state_master.py export <experiment> --out results [detector flags]
```

The whole matrix takes about 25 minutes — 18 minutes of simulation plus
figures and exports. `validate` passes 30/30 checks.
