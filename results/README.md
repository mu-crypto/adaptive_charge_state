# Results

Generated by `adaptive_charge_state_master.py` at commit `008595b`, full sample
size (700 calibration + 1800 test shots per initial state, 300 bootstrap
resamples), physics layer `builtin-reference`.

All 5 experiments were run under 3 detector settings, 15 combinations total:

```
results/<experiment>/<detector>/
    <experiment>_sweep.png      fidelity vs run time, and both speedup curves
    <experiment>_vs_x.png       speedup and fidelity ceiling vs the swept variable
    speedup_table.csv           every target fidelity, both methods, bootstrap CIs
    fidelity_ceilings.csv       best achievable fidelity per method
    summary.txt                 the text summary, as printed by `summary`
```

Detector directories: `ideal`, `det_nonpar_dt50ns_ap0.01_tau100ns` (the
`realistic` preset), `det_nonpar_dt2000ns_ap0.05_tau5000ns` (`stress`).

Not committed, both regenerable: the per-shot pickles (~870 MB — they carry the
correctness and stop-time matrices so the bootstrap can be redone without
re-simulating; `run`) and the per-operating-point figures (13 MB; `plot`).

grid, with the fidelity it occurs at. These are peak values at the edge of what
each configuration can reach, which is also where the bootstrap CIs are widest

## What the sweeps show

**Power.** The speedup is largest at low power (2.0–2.4×) and decays to ~1.4× at
15 µW. Low power means many photons per bright dwell, which is the regime where
the arrival-time pattern carries information the total count does not. At 15 µW
there are ~2.9 photons per dwell and the count is nearly sufficient. Note the
fidelity column moves with it: high power cannot reach high fidelity at any
readout time, so the peak migrates down the fidelity axis.

**Efficiency.** Monotone, and the cleanest statement of the mechanism: 1.05× at
η = 0.02 (0.21 photons per bright dwell) rising to 1.45× at η = 1.0 (10.4 per
dwell). Below about one photon per dwell the event-time statistic stops paying —
the adaptive-count control captures essentially the whole gain there
(1.02× vs 1.05×), so what little is left is adaptive stopping, not the MMPP
filter.

**Switching ratio.** Weakest dependence of the four. The speedup is flat
(1.36–1.40×) from Γ₋₀/Γ₀₋ = 0.5 to 7 and rises to ~1.6× at 100. The fidelity
ceiling, though, climbs steadily with the ratio (0.885 → 0.931 for adaptive
MMPP) and the MMPP advantage over the count threshold widens as the emitter
spends most of its time dark.

**Contrast.** Peaks near C = 0.85 at 1.79×, lower at both ends. At low contrast
neither method reaches high fidelity; at C → 1 the dark state is genuinely dark,
so a plain count threshold is already close to optimal and there is less left to
win.

## Effect of the detector model

Dead time and afterpulsing do **not** overturn the conclusion. Comparing peak
speedups across detector settings, the differences are comparable to the
bootstrap width rather than systematic:

| experiment | ideal | realistic | stress |
|---|---|---|---|
| power, 0.875 µW | 2.00× | 2.07× | 2.08× |
| power, 15 µW | 1.38× | 1.24× | 1.31× |
| contrast, C = 0.85 | 1.79× | 1.82× | 2.01× |
| efficiency, η = 1.0 | 1.45× | 1.38× | 1.43× |
| ratio, Γ₋₀/Γ₀₋ = 100 | 1.62× | 1.44× | 1.52× |

The `realistic` preset (50 ns dead time, 1% afterpulsing) perturbs the recorded
rate by well under a percent, so this is expected there. The `stress` preset is
a real perturbation — 2 µs dead time against an 11.6 µs mean bright-photon
spacing, costing ~12% of clicks — and the speedup still holds, because the
filter is rebuilt from the dead-time/afterpulse-corrected rates and both methods
lose the same photons.

The fidelity *ceilings* are likewise not measurably degraded. Across the 23
operating points, the adaptive-MMPP ceiling shifts by a mean of −0.0013 under
`stress` (range −0.014 to +0.013, 14 of 23 negative) and +0.0004 under
`realistic`. With 1800 test shots per initial state that scatter is what
Monte Carlo noise alone produces, so this matrix does not resolve a ceiling
penalty — it bounds one at roughly ±0.01, not that there is none. Resolving a
smaller effect needs more shots or a common-random-numbers comparison; each
detector setting consumes the RNG differently, so the runs are effectively
independent rather than paired.

Caveat carried in the code: with the detector on, the stream is no longer a
Markov-modulated *Poisson* process, so the MMPP likelihood is approximate and
the reported LLR is a score rather than an exact log-likelihood ratio. Run with
`--no-filter-correction` to see what pure model mismatch costs instead.

## Reproducing

```bash
python adaptive_charge_state_master.py run  <experiment> --out results [detector flags]
python adaptive_charge_state_master.py plot <experiment> --out results [detector flags]
python adaptive_charge_state_master.py export <experiment> --out results [detector flags]
```

The whole matrix takes about 10 minutes. `validate` passes 25/25 checks.
